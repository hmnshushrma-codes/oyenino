Section 3
Zaroori Concepts — Hinglish Mein
Concepts

API, Validation, UNIQUE Constraint, Rate Limiting, CORS

■ API kya hai? Bas ek RASTA jisse frontend backend se baat karta hai. GET = data maangna ("kaunse slots free hain?") POST = naya data bhejna ("ye booking save kar do") ■ Database structure Excel sheet jaisa — rows aur columns: | id | customer_name | phone | date | slot | status | | 1 | Rahul Sharma | 98765xxxxx | 2026-07-15 | 10:00 AM | confirmed | ■ Validation — do jagah kyun? Frontend validation = turant feedback ("phone galat hai") — BYPASS HO SAKTI HAI Backend validation = asli security — BYPASS NAHI HO SAKTI Dono chahiye. Frontend UX ke liye, backend security ke liye. ■ Double-booking kaise rukti hai? Code mein check likhna kaafi nahi — do requests ek saath aa sakti hain. Solution: Database mein UNIQUE rule — "(service + date + time) ka combination do baar nahi ho sakta" Jo request pehle pahunchi wo save, dusri auto-reject. Database khud enforce karta hai. ■ Rate limiting "Ek IP se, ek time window mein, sirf itni requests allowed" Example: 5 booking attempts per 15 min per person. Cloudflare pe dashboard se ek click mein set hota hai — bina code likhe. ■ CORS Jab frontend (yourbusiness.com) aur backend (api.yourbusiness.com) alag domain pe hote hain, browser by default unhe baat karne se rokta hai. CORS = permission list: "sirf yourbusiness.com se requests allowed" Ye na ho toh console mein red error aayega.
Ye concepts samajh lo — phir AI ko prompt likhna 10x aasan ho jayega. Kyunki tumhe pata hoga AI kya kar raha hai aur kyun.

Implementation Phases — Full Checklist
Phase 1 — Day 1

  • Scaffold Hono project with TypeScript

  • Implement POST /waitlist
  • Add CORS middleware
  • Deploy to Cloudflare Workers
  • Set up api.book.oyenino.com DNS
Phase 2 — Day 1-2

Security Layer

  • Set up Turnstile in Cloudflare dashboard
  • Add Turnstile verification middleware to POST endpoints
  • Add rate limiting (Cloudflare's built-in or custom)
  • Add server-side input validation (mirror frontend rules)
  • Add duplicate booking prevention logic
Phase 3 — Day 2

Admin Backend

  • Implement POST /admin/login with PBKDF2 password verification
  • Implement JWT signing/verification middleware using hono/jwt
  • Implement POST /admin/forgot-password (OTP generation + email via Resend)
  • Implement POST /admin/verify-otp (OTP validation + reset token)
  • Implement POST /admin/reset-password (token verification + password update)
  • Implement GET /admin/bookings/today
  • Implement GET /admin/bookings/week
  • Implement GET /admin/bookings/:date
  • Implement PATCH /admin/bookings/:id/cancel
  • Seed admin account via wrangler D1 or setup endpoint
  • Set up Resend account + verify oyenino.com domain
  • Store secrets: JWT_SECRET, RESEND_API_KEY
Phase 4 — Day 2-3

Frontend — Routing & State Persistence

  • Install react-router-dom
  • Refactor App.jsx from useState to BrowserRouter + Routes
  • Set up public routes: /, /book, /confirmation/:id, /slots-unavailable
  • Set up admin routes: /admin, /admin/forgot, /admin/dashboard
  • Build AdminGuard component (JWT check + expiry)
  • Implement sessionStorage persistence for booking flow state
  • Implement localStorage booking receipts (duplicate prevention)
  • Add idempotency key generation on booking submit
  • Add GET /bookings/:bookingId endpoint (for shareable confirmation URL)
  • Replace mock API with real endpoints
  • Add Turnstile widget to booking form
  • Update error handling for backend responses
Phase 5 — Day 3-4

Frontend — Admin Panel

  • Build Admin Login page (email + password form)
  • Build Forgot Password flow (3 steps: email → OTP → new password)
  • Build Admin Dashboard layout with tab navigation (Today / Weekly / Day-wise)
  • Build Today's Bookings view with booking cards + summary
  • Build Weekly view with day-wise bar chart + summary
  • Build Day-wise view with date picker + booking list
  • Add Cancel booking button with confirmation
  • Add Logout functionality (clear JWT from localStorage)
  • Add auth guard — redirect to login if no valid token
  • Wire up admin API calls in src/api/admin.js
Phase 6 — Day 4

Rate Limiting & Security

  • Configure Cloudflare WAF rate limiting rules (Dashboard)
  • Add in-Worker rate limiting middleware (fallback / custom rules)
  • Test rate limits: booking spam, login brute force, OTP spam
  • Verify DDoS protection and Turnstile integration
Phase 7 — Day 4-5

Polish & Ship

  • Test edge cases: past dates, concurrent bookings, bot attempts, page refresh mid-flow
  • Test state persistence: refresh on each step, 30-min timeout, stale date cleanup
  • Test booking rules: same person → day X ✔, day X again ✘, day Y ✔
  • Test admin: wrong password, expired OTP, expired JWT, cancel flow
  • Test routing: back button, direct URL access, 404 fallback, shareable confirmation links
  • Monitor D1 analytics in Cloudflare dashboard
